The whole journey

The factory grows by one pressure at a time.

1Automate

Turn a seed into working software, one task at a time.

2Compose

Make routes, machines, runs and targets explicit.

3Operate

Run work in parallel, watch it live and intervene.

Destination: an observable, steerable system—not one enormous prompt.

How the tutorial works

1Fetch

Your coding agent downloads one homework into spec/.

2Build

Make the feature files pass. They are your acceptance tests.

3Repeat

Fetch again. Existing step definitions carry forward.

You choose the language, libraries and design.

First things first

Get started

Fork the starter, open it in a Codespace, sign in with ChatGPT, then fetch Homework 1 in the Codex chat.

1 · Fork the starter

Your fork becomes your capstone repository.

  1. Open capstone-project-starter.
  2. Choose Fork.
  3. Give the fork your capstone project’s name.
The homeworks build Tetris first. Your capstone comes later.

2 · Open and check

On your fork, choose Code → Codespaces → Create codespace. Sign in twice with ChatGPT, then check the tools without calling a model.

  1. Codex extension, your coach: open Codex in the sidebar, then Sign in with ChatGPT.
  2. Pi, which your factory runs: in the terminal, pi, then /login → OpenAI Codex (legacy) → Device code login.
bin/doctor --agent codex

Working locally instead? git clone https://github.com/YOUR-NAME/YOUR-CAPSTONE.git, then run bin/doctor in it.

Ready means: Bash, Git, Node, npm and all three agent CLIs are present, and Pi and Codex are signed in.

Pi signs in with a device code, which is off by default. Before signing in, turn on “Enable device code authorization for Codex” in ChatGPT Settings → Security; on a Business or Team workspace, an admin enables it under Permissions & Roles. The Codespace runs bin/doctor once when it is first built; warnings that Pi and Codex are not signed in are expected until you sign in. The Codex extension and the codex CLI share one sign-in, so bin/doctor sees the extension's. Type /quit to leave Pi after signing in.

3 · Start your coding agent

Open the Codex chat panel. It works at the repository root, where your agent finds its instructions and skills.

Check: Codex is working in the root of your fork. Your factory source will live in factory/.

Prefer a terminal agent? Start pi, claude or codex at the repository root instead.

The agent must start at the repository root, where AGENTS.md and the project skills live. The Codex extension opens on the Codespace's folder, which is the root.

Homework 001

Basic unvalidated loop

Seed

Describe the product: terminal Tetris.

Plan

The agent breaks the seed into tasks.

Do

One pass completes one task and commits it.

Factory gainsA small, stateless loop that turns a seed into working code.
The factory does not inspect plan.md. The agent owns the plan and returns structured JSON; the factory routes on fields, not prose.

Run your first factory

From the repository root, give every run the seed and its target:

Write the plan
bin/factory \
  --seed tetris/spec.md \
  --target tetris/tetris-001
Do one task
bin/factory \
  --seed tetris/spec.md \
  --target tetris/tetris-001
Finish the plan
bin/factory \
  --seed tetris/spec.md \
  --target tetris/tetris-001 --all
Play the result
npm --prefix \
  tetris/tetris-001 start
Small win: a real game appears, one agent task and one commit at a time.

Bonus · Try another model

See how much the model changes what your small factory produces.

1Keep your baseline

Leave tetris/tetris-001 unchanged for the next homework.

2Switch models

Pass a model choice to your harness. Build twice into fresh targets.

3Compare

Time the runs, play the games and decide which output you prefer.

Keep this informal. You do not need to build a benchmarking framework.

Later homeworks move model choice into machine configuration, combine several models’ judgements and track token cost.

Homework 002

Checking the work

Planner

Keeps and advances the plan.

Doer

Implements the next task.

Validator

Checks through a lens you choose.

Factory gainsSpecialised machines, validation findings and bounded retry.

Bonus · Change the lens

Run the same validator with a different concern in mind.

1Choose a lens

Switch to security, usability or another concern.

2Build again

Keep the seed and model. Use a fresh target named for the new lens.

3Trace the impact

Follow findings into subtasks, then into changes in the code.

What changed because the validator looked for something different?

Leave tetris/tetris-002 unchanged. Compare only differences supported by recorded validator findings; two model runs can differ anyway. No difference is a useful result.

Homework 003

Machine configuration

Each machine's folder becomes its harness's configuration.

  • AGENTS.md: what the machine is for, and its lens
  • Configuration: its harness and model, and its own login
  • Change a machine without changing factory code
Factory gainsMachines configured as data, on any harness.

Homework 004

The assembly line

The route leaves your code and becomes a graph the factory reads.

  • Machines are named nodes
  • Result fields choose labelled edges
  • Change the route without changing factory code
Factory gainsA configurable workflow instead of a hard-coded sequence.

Homework 005

Runs and targets

Factory

Keeps nothing of a run: only its own code.

Line

A folder in the target: its graph, its machines and its runs.

Run

Remembers its line and seed; its plan and record are committed on its line.

bin/factory --run tetris --target tetris/tetris-005 --line careful --seed tetris/spec.md
Factory gainsMany resumable runs across many codebases.

Homework 007

Watching

The factory becomes a service. Start a run, get your terminal back, then attach.

./factory --run tetris …
# started run tetris

./factory watch tetris --target …
# planner | …
# doer    | …
# tokens  | …

Machines speak ACP: the Agent Client Protocol. Output and token usage stream as they work.

Factory gainsBackground runs, durable output and live cost visibility.

Homework 008

Steering

Watching becomes a conversation. Send a message to the machine working now.

./factory say tetris --target … doer \
  "use curses, not print"

A message belongs to that machine run. For a lasting instruction, change the seed, the plan or the machine's AGENTS.md.

“I can see what you’re doing—and redirect you before the turn ends.”
Factory gainsTargeted, live intervention in running agent work.

Keep the learning loop small

Do
  • Treat features/ as the spec
  • Take one failing example at a time
  • Keep state in files
  • Route on structured results
Don’t
  • Edit the fetched spec
  • Hide intelligence in factory code
  • Parse an agent’s prose
  • Build all eight homeworks at once
